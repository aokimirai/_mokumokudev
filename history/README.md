# history

人とAIがどのようにやり取りし、開発を進めてきたかを記録するディレクトリ。
最終的に、ここに蓄積した記録を元に開発工程を書籍化する。

## 目的

- 人がAIに何を依頼し、AIが何を返し、人がそれをどう判断したかを時系列で残す。
- 書籍の「判断ボックス」(人間が判断したこと / AIに任せたこと)の素材にする。

## 他ディレクトリとの違い

| ディレクトリ | 内容 |
| --- | --- |
| `history/` | 開発の過程(やり取りの経緯)の記録 |
| `docs/` | 開発の成果物(要件定義、設計書など) |
| `books/` | 書籍の原稿 |

## ファイル構成

要件定義書の章立て案(開発工程)と同じ構成にする。1章1ファイルで、各ファイルの末尾に判断ボックスを置く。

| ファイル | 開発工程 |
| --- | --- |
| [01_企画・要件定義.md](01_企画・要件定義.md) | 何を作るか、誰の課題を解くか |
| [02_データ構造・DB設計.md](02_データ構造・DB設計.md) | データ構造・DB設計 |
| [03_権限・ワークフロー設計.md](03_権限・ワークフロー設計.md) | 権限・ワークフロー設計 |
| [04_LLM連携設計.md](04_LLM連携設計.md) | プロンプト、事前フィルタの仕組み |
| [05_ローカルLLMにおぼれてみる.md](05_ローカルLLMにおぼれてみる.md) | ローカルLLMの試行錯誤 |
| [06_実装.md](06_実装.md) | 実装 |
| [07_テスト・振り返り.md](07_テスト・振り返り.md) | テスト・振り返り |

## 要検討事項

- [x] ファイル名の規則 → 章立てに合わせて `NN_工程名.md`
- [ ] 記録の追記タイミング(例:作業セッションごと / 1日ごと / 工程の区切りごと)
- [ ] 「やり取りの記録」に書く中身のフォーマット(例:日付、依頼内容、AIの提案、人間の判断、結果、気づき)
- [ ] 誰が書くか(人が書く / AIが下書きして人が確認する)
